# ADR-0012. Резервная копия БД и проверка восстановления

Статус: **принято**. Дата: 14.10.2026. Требования: ТЗ harness ENV-03 (`make db-backup`, `make db-restore-check`), H-24.

## Решения

1. **Копия** (`make db-backup`) — `pg_dump` в custom-формате из контейнера `db`, без владельцев и прав. Рядом манифест:
   коммит приложения, ветка и признак незакоммиченных изменений, версия PostgreSQL, размер и SHA-256 дампа, отпечаток БД.
   - Папка — `.local-audit/backups/<время UTC>-<коммит>/`, вне Git, права только у владельца (0700/0600): в dev-БД лежит
     копия реальных данных legacy.
   - Отпечаток снимается до и после дампа. Если БД менялась во время копирования, копия делается заново (до трёх раз).
2. **Отпечаток** (`scripts/sql/db-fingerprint.sql`):
   - по каждой таблице — число строк и MD5 строк без учёта порядка;
   - по каждой последовательности — последнее значение, чтобы новые записи продолжили нумерацию;
   - по схеме — столбцы, типы, обязательность, значения по умолчанию, правила сортировки, ограничения и индексы.
   - Настройки сессии (пояс, формат дат и чисел) фиксированы, иначе текст строк зависел бы от сервера.
   - Выражение CHECK после восстановления PostgreSQL печатает с другой, равнозначной расстановкой приведений типов.
     Поэтому CHECK сравнивается по таблице, имени и столбцам, остальные ограничения — по полному определению.
3. **Проверка восстановления** (`make db-restore-check`, по умолчанию — последняя копия) работает так:
   - сверяет SHA-256 дампа;
   - поднимает временный контейнер того же образа PostgreSQL без сети, с данными в памяти;
   - восстанавливает копию и сравнивает отпечаток с манифестом.
   dev-БД не затрагивается; результат — `restore-check.json` рядом с копией, при любом расхождении — ненулевой код.
4. **Где проверяется:**
   - каждый аудит выполняет шаг `backup` (`TGT-BACKUP`, обязательный) на своей синтетической БД после миграций;
   - самопроверка H-24 делает то же на временной БД сервиса `db` и убеждается, что подменённый отпечаток и
     повреждённый дамп отклоняются.
   `make check` копий не делает: dev-БД с реальными данными копируется только по явной команде.

## Не сделано

- Восстановление приложения целиком на чистой машине (код, `.env`, копия БД) — на репетиции переноса (ERP-069/074).
- Хранение копий вне рабочей машины и расписание копирования — решение по инфраструктуре заказчика (D-01).
