# ADR-0054. «Финансы» → «📈 Маржинальность»: маржинальность по категориям

Статус: **принято**. Дата: 24.10.2026. Ответ бухгалтера 23.10, № 36: формулы отчётов — как есть. Требования: ERP-060,
M11.MARGIN.

## Контекст

Вкладка legacy «📈 Маржинальность» состоит из двух частей:

- «Маржинальность по категориям (оценка — без техкарт)» (`renderCategoryMargin`/`exportCategoryMarginExcel`): выручка
  реализации по категориям и месяцам, материалы — оценка себестоимости P&L по ЭСФ, труд + ОПР месяца из P&L, разнесённые
  по долям выручки;
- маржа по позициям заказов (`renderMarginReport`/`openMarginDetail`): материалы и труд позиции по техкартам и нормам.

## Решения

1. **Маржинальность по категориям считает сервер** (`PlRevenue::categoryMargin`) за выбранный год, точными суммами, так
   же, как legacy: категория реализации — по каталогу (как в «Выручке по категориям»), материалы ЭСФ «Товары» делятся
   между подходящими категориями по выручке месяца, труд + ОПР — сдельная и ОПР из P&L за каждый месяц года, делятся по
   доле категории в выручке месяца. Порядок — по выручке года. Строки приходят только при открытой вкладке (`cm_year`).
2. **Выгрузка** — как legacy: лист с годом, по месяцам маржа и процент, итог года.
3. **Маржа по позициям заказов не переносится сейчас.** В legacy нет техкарт, а нормы труда не совпадают ни с одной
   категорией изделий: каждая позиция показывает маржу, равную выручке, 100 %. Она появится вместе с техкартами
   (ERP-028, решение D-12); на её месте — сообщение.
4. **Права** — страница «Финансы».

## Проверка

- `PlRevenueTest`: категория по каталогу, товар вне каталога не входит, ткань января — диванам, порядок по выручке года,
  по месяцам.
- **Сверка с legacy** — `make pl-compare`: маржинальность по категориям — каждое число в целых тенге, совпадает за 2025 и
  2026.
