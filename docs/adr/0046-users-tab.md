# ADR-0046. «Сотрудники» → «Пользователи»: учётные записи

Статус: **принято**. Дата: 23.10.2026. Решение D-13 (23.10.2026), ADR-0045. Требования: ERP-053, ERP-011.

## Контекст

Во вкладке legacy «Пользователи» директор и HR ведут учётные записи:
- список: встроенные роли и записи `app_users` — логин, имя, подпись роли, разделы, пароль, код ЗП, состояние;
- форма: логин, пароль, имя, подпись роли, шаблон роли, канал продаж, разделы;
- блокировка и разблокировка;
- ниже — сотрудники с кодами ЗП и входом в систему, «＋ Создать вход» для сотрудника без входа.

После решения D-13 учётные записи перенесены как в legacy (ADR-0045). Значит, их можно вести здесь.

## Решения

1. **Кто может.** Вкладка и все действия — директор и «Бухгалтер/HR», как в legacy. Сервер проверяет каждое действие
   (`UserAccountService`), остальным роли список учётных записей не отдаётся.
2. **Новая учётная запись** (legacy `saveAppUser`): логин (латиница, цифры, точка, дефис, подчёркивание; приводится к
   нижнему регистру), пароль, имя, подпись роли, канал, разделы из списка legacy. Занятый логин — «Логин уже занят». Роли
   у новой записи нет, как в legacy: её права — отмеченные разделы и канал.
3. **Правка:** имя, подпись, канал, разделы, новый пароль (пусто — не менять). Разделы, которых нет в форме legacy
   (например «Продажи», «Входящие ЭСФ»), сохраняются. Legacy их терял при сохранении (ADR-0002 п. 113). У директора
   разделы шаблона остаются всегда.
4. **Блокировка** (legacy `toggleUserActive`): «Нельзя заблокировать самого себя»; директора заблокировать нельзя
   (legacy снимал такую блокировку при входе). Заблокированный сразу теряет доступ, его сессии завершаются.
5. **Пароли — только хешами.** Колонка «Пароль» показывает «••••••». Legacy показывал пароль по нажатию (п. 114). Пароль —
   не короче 8 символов; legacy требовал 4. Смена пароля завершает сессии этой учётной записи.
6. **Каждое изменение** — с версией записи (два администратора не перезапишут друг друга незаметно) и в журнале аудита,
   без паролей.
7. **Позже:**
   - коды ЗП (PIN) сотрудников: колонка «Код ЗП» — «—», «🔑» и «🔑 Выдать 6-значные коды» отвечают сообщением, фильтры
     по коду пусты. PIN выдаются заново с кабинетом (ERP-058, вопрос № 42; п. 115);
   - «🗑 Удалить» не перенесено: учётную запись блокируют, а не удаляют, чтобы журнал аудита сохранил автора (п. 116).

## Проверено (23.10.2026)

- `UserAccountTest`:
  - новая учётная запись: короткий пароль, занятый логин и раздел не из формы отклоняются; логин приводится к нижнему
    регистру; права — отмеченные разделы и канал; в аудите нет пароля;
  - правка сохраняет разделы, которых нет в форме; пустой пароль не меняет пароль; устаревшая версия отклоняется;
  - блокировка: себя и директора нельзя; заблокированный теряет все разделы; разблокировка;
  - только директор и HR создают, правят и видят учётные записи; пароль в список не попадает.
- Реестр — непросмотренных 0.
