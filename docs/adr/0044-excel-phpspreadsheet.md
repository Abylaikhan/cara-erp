# ADR-0044. Excel на сервере: PhpSpreadsheet

Статус: **принято**. Дата: 23.10.2026. Решение заказчика: 23.10.2026, вариант «А» вопроса № 65 (`docs/open-questions.md`,
таблица «Что нужно от заказчика»). Требования: ERP-067, ERP-034 (загрузка выписок).

## Контекст

Legacy работает с Excel в браузере: библиотеки SheetJS 0.18.5 и ExcelJS 4.4.0 подгружаются со сторонних серверов (CDN)
при каждом открытии страницы. Так устроены 28 выгрузок и 5 загрузок. Новые зависимости добавляются только с согласия
заказчика, поэтому до решения эти кнопки отвечали сообщением (ERP-067).

Варианты были такие:
- **А.** PhpSpreadsheet на сервере;
- **Б.** библиотека в браузере, как в legacy;
- **В.** без библиотеки: CSV или свой XLSX.

## Решения

1. **Библиотека** — `phpoffice/phpspreadsheet` 5.10.0, лицензия MIT, версия закреплена в `composer.lock`. Обновление — как
   у остальных зависимостей: отдельной задачей, с `composer audit`.
2. **Образ PHP** получил расширение GD (`libpng-dev`, `docker-php-ext-install gd`): без него библиотека не ставится. Версии
   базовых образов не менялись.
3. **Файлы создаёт и разбирает сервер.** Код со сторонних серверов в браузер не грузится. Загруженный файл разбирается на
   сервере, его размер ограничен, строки проверяются до записи.
4. **Текст в ячейках записывается как текст.** Значение, которое начинается с `=`, не становится формулой. Legacy (ExcelJS)
   тоже писал строки как строки; формулы — только там, где их ставит сама выгрузка.
5. **Что переносится сейчас** — выгрузки перенесённых экранов и загрузка выписки в «Сверку с банком» (сырые строки, без
   проведения денег). Выгрузки и загрузки неперенесённых разделов переносятся вместе с ними:
   - P&L, ОСВ, виды деятельности — D-11, D-12;
   - центры прибыли — D-11;
   - кабинет — D-13;
   - рабочий лист и факт производства — D-05, D-06;
   - перенос выписки в журнал — D-03, D-11.

6. **Как устроено.** Все выгрузки перенесённых экранов в legacy — SheetJS `aoa_to_sheet` + ширины колонок, без оформления.
   Страница собирает те же строки, что legacy, и отправляет их на `POST /export/xlsx`. Сервер (`XlsxFromRows`) пишет
   книгу:
   - число — числом, текст — текстом;
   - ширина колонки — по формуле SheetJS (`wch` → ширина);
   - несколько листов, имя листа без запрещённых символов.

   Выгрузить может только тот, кому открыта страница; каждая выгрузка — в журнале аудита (имя файла и число строк, без
   содержимого). Из базы при этом ничего не читается: в файл попадает то, что страница уже показала.

   Исключение — «📥 Товары в Excel» во «Входящих ЭСФ»: legacy читал все строки товарных ЭСФ из базы, здесь их читает и
   собирает сервер (`GET /esf/export-goods`).
7. **Перенесены выгрузки:**
   - «Журнал работ», «Рабочий лист производства»;
   - «Реализация», акт сверки, «Дебиторка», ДДС и окно детализации;
   - «Касса» → «Выдано по сотрудникам»;
   - «Зарплатная ведомость» и журнал выдач;
   - товары ЭСФ.

   Отличия — ADR-0002 пп. 117–119. Выгрузка P&L — с отчётом P&L (D-11, D-12).

## Проверено (23.10.2026)

- Образ PHP пересобран с GD; `composer require phpoffice/phpspreadsheet:5.10.0` добавил её и 4 зависимости
  (`maennchen/zipstream-php`, `composer/pcre`, `markbaker/complex`, `markbaker/matrix`). Версии остальных пакетов не
  изменились. `composer audit` — уязвимостей нет; `make check` проходит.
- `XlsxExportTest`:
  - число остаётся числом, текст — текстом, текст с `=` не становится формулой;
  - ширины колонок — по формуле SheetJS;
  - выгрузить может только тот, кому открыта страница; имя файла очищается; выгрузка — в аудите без содержимого.
- `EsfGoodsExportTest` — строки товарных ЭСФ и угаданный склад, как в legacy.
- Сверка с legacy на тех же данных (`make visual-filters`, обе темы): legacy выгружает через подменённый SheetJS, который
  записывает листы, строки и ширины; страница здесь — через перехват запроса. Совпадают:
  - акт сверки, «Реализация», «Журнал работ», рабочий лист производства;
  - «Касса» → «Выдано по сотрудникам»;
  - «Дебиторка», ДДС, окно детализации;
  - зарплатная ведомость и журнал выдач.

  Не сравниваются строка с датой отчёта и имя файла (ADR-0002 пп. 73, 117), а в «Дебиторке» — дни просрочки, статус и
  порядок строк: legacy не распознаёт срок оплаты (п. 69).
