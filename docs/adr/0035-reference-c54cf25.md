# ADR-0035. Эталон legacy — `c54cf25`

Статус: **принято**. Дата: 20.10.2026. Решение заказчика: 20.10.2026, прислан `index.html` этой версии и выбран вариант
«А» вопроса об эталоне (`docs/decisions-request.md`, таблица «Что нужно от заказчика», п. 31). Требования: ERP-001, ERP-075.

## Контекст

Принятым эталоном был `8d275a1` (15.10). После него в legacy вышло 11 коммитов, последний — `c54cf25` (19.10 19:43). Его
`index.html` заказчик прислал 20.10 (`docs/index.html` вне репозитория). Blob совпадает: `8777f7bb`, SHA-256
`26f61eb3…`. Коммит `3f275bc` страницу не менял.

## Решения

1. **Эталон** — `c54cf25` (`tools/harness/config.json` → `source.accepted_ref`). Визуальная сверка, сверка фильтров,
   реестр и аудит читают его. Снимок лежит в `.local-audit/blobs`. Требования, проверенные на `8d275a1`, сохраняют свою
   ссылку в `requirements.csv`.
2. **Перенесено в разделы, которые уже есть:**

   | Изменение legacy | Где | Коммит |
   |---|---|---|
   | Остаток кассы после каждой операции по всей истории кассы (по дате, в дне сначала приходы); не зависит от сортировки, фильтров и периода; подсказка у заголовка | «Деньги» → «Касса» | `c699dea` |
   | Номер позиции товара в заказе (№1, №2…) | «Производство» → журнал | `c699dea` |
   | Период «День» с выбором даты; у «Месяца» — список месяцев с операциями | «Деньги» | `0cca3f6` |
   | Дата начала позже окончания подтягивает окончание | «Деньги» | `c54cf25` |
   | «👥 Кому выдано» только у зарплатных расходов «Кассы ЗП» (не салонов); окно показывает выплаты ведомости, привязанные к расходу (по операции, номеру документа или сумме), иначе — «не привязаны» | «Деньги» → «Касса» | `b2eb1ce` |
   | «🔁 Сверка переводов на кассу ЗП»: по датам переводы из банков против поступлений в кассе, переводы между своими счетами без пары | «Деньги» → «Касса» | `83385ee`, `6630d36` |
   | «Расход денег» на графике ФОТ — всё, что выдано из «Кассы ЗП», кроме переводов между кассами; пояснение под графиком | Дашборд | `830a998` |

   «Кому выдано» стал возможен после переноса выплат ведомости (ADR-0033). По той же причине на дашборде теперь есть
   «ФОТ (месяц)» и столбцы «Начислено» — из начислений ЗП.
3. **Ждёт своих разделов или решений:**
   - исправления в сверке переводов (удаление и создание поступлений), форма перевода (только дата, сумма, счета и
     описание) и удаление перевода вместе с парной операцией — меняют денежные операции: проведение денег (ERP-031…033,
     D-03, D-11), ADR-0002 п. 92;
   - номер позиции в рабочем листе производства (там же поиск по «№N»), доске цехов, загрузке, журнале работ, задачах,
     накладных, карточке заказа, кабинете и выгрузках — эти части не перенесены (ADR-0002 п. 53, D-05, D-06, D-08);
   - номер позиции в строке накладной (`sales_worksheet.item_no`, скрипт `item_no.sql` в Supabase) — с рабочим листом
     реализации (D-08). В снимке Supabase от 19.10 столбец уже есть (скрипт выполнен), у всех 58 строк он пуст:
     накладные созданы раньше.
4. **Отличия, которые закрылись:** legacy исправил сдвиг периода «Денег» на день через UTC (ADR-0002 п. 54 изменён);
   «👥» больше не сообщение (п. 55).

## Проверено (20.10.2026)

- Визуальная сверка с `c54cf25`, оба режима оформления: 138 снимков, самое большое отличие 0,26 %. «Деньги» — 0,05 % и
  0,06 %, окно сверки переводов — 0,01 %, дашборд — 0,01 %, производство — 0,02 % и 0,04 %.
- Таблица «Кассы» как текст по всем 5 кассам (остаток после каждой операции, кнопка «👥») — совпадает; текст окна
  «🔁 Сверка переводов» — совпадает.
- Фильтры и сортировки (AC-08): «Касса» 33 случая, «Расчётные счета» 34, «Все операции» 19, журнал производства 50 —
  совпадает (записанные отличия прежние).
- Реестр (AC-09) по новому эталону: непросмотренных 0. `make check` — 283 теста, самопроверки harness — 25.

**Период «День» и выбор месяца** сверяются с 20.10 (ADR-0036): день, текущий месяц и другой месяц из списка. Подпись
периода, таблица кассы и список месяцев совпадают.
