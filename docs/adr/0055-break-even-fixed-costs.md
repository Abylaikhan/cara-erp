# ADR-0055. «Финансы» → «Точка безубыточности»: постоянные затраты — план и факт

Статус: **принято**. Дата: 24.10.2026. Ответ бухгалтера 23.10, № 36 и D-11: формулы отчётов — как есть. Требования:
ERP-060, M11.BEP.

## Контекст

Вкладка legacy «Точка безубыточности» (`loadFixedCostsPeriod`/`renderFCPlanTable`/`saveAllFixedCosts`/`renderBEPKpi`/
`renderBEPChart`) состоит из:

- плана постоянных затрат месяца: статья, категория (статьи расходов с признаком «постоянная»), план, день оплаты, факт из
  журнала операций, отклонение, «✓ Проведено»; legacy сохранял месяц сам через секунду после изменения — удалял его и
  записывал заново (таблица `fixed_costs`, в legacy пустая);
- структуры и разбивки по категориям проведённых строк;
- KPI и графика точки безубыточности за период страницы — по постоянным затратам и марже из P&L.

## Решения

1. **План месяца хранит сервер** (`fixed_costs`, `FixedCosts`). Месяц без плана показывает план предыдущего месяца (не
   сохранён, не проведён), иначе статьи с признаком «постоянная» с планом 0. Примерный список legacy не используется
   (ADR-0002 п. 126).
2. **Сохранение — как в legacy, сам, через секунду после изменения**; «✓ Проведено» — сразу. Месяц заменяется целиком в
   одной транзакции и только если с момента загрузки его никто не сохранил; иначе — «изменены другим пользователем».
   Название обязательно, план не отрицательный, день оплаты — 1…31.
3. **Факт статьи** — расходы месяца в журнале операций, где статья — категория или подкатегория операции, плюс строки
   авансовых отчётов месяца с этой категорией; считает сервер точными суммами.
4. **KPI и график** — постоянные затраты, маржинальность и выручка из P&L за период страницы (ADR-0052); точка
   безубыточности = постоянные затраты / маржинальность.
5. **Отличия от legacy** — ADR-0002 п. 127: месяц списка совпадает с подписью, факт — за весь месяц, подсказка под графиком
   показывается, новая строка получает первую статью списка, добавление и удаление строки сохраняются.
6. **P&L не берёт план**: legacy при отсутствии операций постоянных затрат подставлял план месяца, открытого на этой
   вкладке (если её открывали в этой сессии); здесь — 0, как другие запасные варианты (п. 126).
7. **Платёжный календарь** («Деньги» → «📋 Плановые расходы») берёт проведённые строки плана текущего месяца, как
   legacy их раскладывал: статья с днём оплаты — в этот день каждого месяца; аренда, коммунальные, связь, банк,
   страхование — 1-го числа; ФОТ — долг в ближайшую пятницу и четверть каждую пятницу; остальное — поровну по рабочим
   дням горизонта (если больше ₸100 в день). Legacy брал план месяца, последним открытого на вкладке ТБУ, и только если
   её открывали в этой сессии.
8. **Права** — страница «Финансы»; сервер проверяет право на сохранение. Каждое сохранение — в журнале действий.

## Проверка

- `FixedCostsTest`: месяц без плана — статьи «постоянная» по порядку, иначе предыдущий месяц по названию без «проведено»;
  факт — по категории и по статье (одна операция — один раз), последний день месяца, авансовый отчёт, без прихода и
  другого месяца; сохранение целиком, отказ поверх изменённого месяца, удаление всех строк; проверки строки, права,
  страница получает нужный месяц.
- `make e2e` (ТБУ): новая статья с планом, «✓ Проведено» — в «Структуре», сохранено само и осталось после перезагрузки;
  с днём оплаты — в платёжном календаре в этот день.
- `MoneyJournalTest`: календарь получает только проведённые строки текущего месяца с планом.
