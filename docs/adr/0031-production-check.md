# ADR-0031. Проверка режима production (AC-78)

Статус: **принято**. Дата: 19.10.2026. Требования: TEST-AC-78 («Чистая установка и production build: инструкции
воспроизводимы; нет встроенных паролей/ключей, ошибки сборки отсутствуют»), часть ERP-077; ТЗ OPS-01.

## Контекст

Где будет рабочий сервер, ещё не решено (D-01), но само приложение в режиме production проверить можно уже сейчас. До
этого аудит и `make check` собирали и тестировали код только в режиме разработки. HTTP-проверка смотрела лишь `/up` и
`/login` при `APP_ENV=local`.

## Решения

1. **`make prod-check`** (`scripts/check.sh build prod`). Шаг `prod` поднимает отдельный экземпляр образа приложения:
   - `APP_ENV=production`, `APP_DEBUG=false`, временная пустая БД;
   - кэши настроек, маршрутов, событий и шаблонов — в `/tmp` этого экземпляра;
   - файл сервера разработки Vite (`public/hot`) не учитывается: путь к нему задаёт `VITE_HOT_FILE`, по умолчанию
     ничего не меняется.

   dev-БД и dev-кэши не затрагиваются. Временная БД и экземпляр удаляются в конце, при ошибке тоже. Проверка идёт
   рядом с работающим dev-окружением.
2. **Что проверяется** — любое отклонение даёт ненулевой код:
   - **настройки PHP** — ошибки пишутся в журнал и не выводятся на страницу (`display_errors=Off`, `log_errors=On`),
     версия PHP не отправляется;
   - **отказы** — миграции проходят в режиме production, синтетический сид и `legacy:import` отказываются работать;
   - **режим** — `artisan about`: production, отладка выключена, кэши собраны (`config:cache`, `route:cache`,
     `view:cache`);
   - **страницы** — `/login` грузит собранные ресурсы, а не сервер разработки; нет заголовка `X-Powered-By`; cookie
     сессии `HttpOnly`;
   - **гость** — `/dashboard` отправляет на `/login`;
   - **ошибки** — страницы 404 и 419 (запрос без CSRF) не показывают код, пути, SQL и стеки;
   - **сборка** (`public/build`) — нет секретов из `.env`: ключа приложения, паролей БД и разработки, адреса и ключа
     Supabase. Нет и шаблонов токенов и закрытых ключей (JWT, `BEGIN … PRIVATE KEY`, `service_role`).
3. **Ежедневный аудит** выполняет этот шаг как обязательную проверку `TGT-PROD` на чистой копии кода, после сборки.
4. **Образ PHP.** `docker/php/php.ini` дополнен: `display_errors = Off`, `display_startup_errors = Off`,
   `log_errors = On`. Раньше действовали значения PHP по умолчанию: ошибки выводились на страницу и не писались в
   журнал. Приложение показывает свои страницы ошибок, а с `APP_DEBUG=true` в разработке — подробные. Ошибки уровня
   PHP теперь идут в журнал контейнера.

## Проверено (19.10.2026)

- `make prod-check` — все пункты проходят; контейнеров и временных БД после проверки не остаётся.
- Подложенный в сборку шаблон токена проверка находит и останавливается.
- Ошибка самой проверки найдена при отладке и исправлена: `view:cache` очищает папку скомпилированных шаблонов, поэтому
  шаблонам нужна своя папка, отдельно от кэшей настроек и маршрутов.

## Найдено: Inertia DevTools записывал реальные данные (19.10.2026)

В списке маршрутов без входа оказались маршруты Inertia DevTools (`_inertia/devtools/*`, часть `inertia-laravel` 3).
- **Production:** закрыто. Без `APP_ENV=local` DevTools выключен и маршруты отвечают 403.
- **Разработка:** DevTools записывал каждый запрос вместе с props в `storage/inertia-devtools/`: 716 файлов, 684 МБ.
  dev-приложение работает на копии реальных данных, поэтому эти файлы содержали реальные данные вне `.local-audit/` и
  локальной БД (правило CLAUDE.md). В Git файлы не попадали: каталог исключён своим `.gitignore`, cookie в записях
  замаскированы.

**Исправлено:**
- `INERTIA_DEVTOOLS_ENABLED=false` в `.env.example` и в местном `.env`;
- накопленные записи удалены;
- `make doctor` проверяет, что DevTools не пишет запросы.

Выдача файлов `storage/{path}` (локальный диск, `serve`) требует подписанной ссылки, а приложение таких ссылок не
выдаёт: файлы проектов отдаются только через контроллер с проверкой прав.

## Не сделано (на этапе развёртывания, D-01)

- HTTPS: `SESSION_SECURE_COOKIE=true`, HSTS, конфигурация nginx с TLS.
- Хранение журналов и копий вне сервера.
- Первый пользователь production: синтетический сид в production отказывает. Создание реальных пользователей — с D-13.
