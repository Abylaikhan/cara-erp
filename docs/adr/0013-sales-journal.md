# ADR-0013. Продажи (M09): перенос заказов, журналы и отчёт (просмотр)

Статус: **принято**. Дата: 14.10.2026. Источник legacy: page-sales L3824–4133; `loadOrdersFromDB` L1356;
`showPage('sales')` L16390; `getOrderSortValue`/`resolveCustomerName`/`orderTotal`/`setOrderYear`/`setOrderMonth`/
`clearOrderFilters`/`sortOrders` L29892–29980; `renderOrders` L30002–30237; `updateOrderTabCounts`/`showSalesTab`
L30240–30751; `markOrderDone` L31140.

## Решения

1. **Что сделано.** Журнал «Все заказы» и вкладки «Очередь», «В работе», «Завершено» — фильтры, сводка, сортировка и
   таблица как в legacy, по заказам каналов пользователя (`ChannelScope`). Сумма заказа — сумма строк, «Оплачено» —
   сохранённый в заказе процент оплаты.
   - Legacy показывает этот же процент, пока не загружены денежные операции. Когда они загружены (дашборд, «Деньги»),
     `loadMoneyFromDB` пересчитывает процент по приходам с номером заказа и `order_payments`, и число на экране
     зависит от порядка открытия страниц.
   - В перенесённых данных у 538 заказов есть такие оплаты, у 93 из них пересчёт даёт другой процент: у 85 больше,
     у 8 меньше. Какой источник верен — решение D-03; пересчёт придёт с разделом «Деньги» (ERP-031/032).
2. **Что не сделано и почему.** Заказы пока не создаются и не меняются:
   - сохраняемая цена (D-02) и состав и идентичность строк (D-12) не решены, поэтому «+ Новый заказ» и клик по заказу
     сообщают, когда это появится (ERP-029/030);
   - «Рабочий лист реализации» — вместе с проведением реализации (ERP-049/050, D-08).
3. **«✓ Завершить»** — единственное действие этой части, правило legacy: заказ дилера, не завершён и не отменён,
   реализован не меньше чем на 99 % суммы. Legacy проверял это только для показа кнопки; здесь правило проверяет сервер,
   изменение пишется в журнал с версией записи.
   - На деле кнопка в legacy почти не видна: при каждой загрузке реализаций `autoCompleteOrders` сам завершает такие
     заказы, а остальные — при реализации ≥ 99 % и оплате 100 %. В перенесённых данных подходящих незавершённых
     заказов нет ни одного, legacy их уже завершил.
   - Запись при чтении здесь не повторяется: автозавершение войдёт в проведение реализации (ERP-050, решение D-08).
4. **Данные.** `make legacy-import ENTITY=orders`, затем `ENTITY=realizations`:
   - перенесено 3124 заказа, 4152 строки и 1338 реализаций; SQL-сверка всех полей — 0 расхождений;
   - сумма всех строк и выручка всех реализаций совпадают с копией legacy до копейки (суммы в публичный репозиторий не пишутся).
   - Строки заказа стоят в естественном порядке legacy (`legacy:natural-order order_items`, только GET): на номер
     строки ссылаются прогресс производства и рабочие листы.
   - Даты legacy хранит текстом трёх видов (ISO, ISO со временем, ДД.ММ.ГГГГ, ДД.ММ.ГГ). Здесь это даты, прочитанные
     как в legacy: время отбрасывается, двузначный год — 20ГГ.
   - 288 реализаций ссылаются на номера заказов, которых нет; они перенесены без связи с заказом.
   - Повторный импорт ничего не меняет. Строку, удалённую в legacy, он удаляет (заказы здесь пока только читаются).
     Если исчез сам заказ, импорт отклоняется для разбора.
5. **Журнал реализации** (вкладка «Реализация», часть 2). Фильтры по месяцу, году, датам, каналу, оплате и поиску,
   итоги, таблица и строка «Итого» — как в legacy; строки загружаются при первом открытии вкладки.
   - Офисные роли видят и строки без заказа, как в legacy; салон и дилер — только строки своих заказов.
   - Legacy сортирует только по дате, порядок внутри одной даты у него не определён. Здесь внутри даты — по времени
     проведения.
   - Исправлено (ADR-0002, п. 48–49): «Все даты» показывает все даты (legacy сразу возвращал текущий месяц); список лет —
     по датам реализаций (legacy читал поле, которого у реализаций нет, и показывал только текущий год); заказ «В работе»
     показан «🔨 В работе», а не «⏳ В очереди».
   - «📥 Excel» — с остальными выгрузками (ERP-067): для `.xlsx` нужна библиотека, новые зависимости ставятся отдельной
     задачей.
6. **Отчёт по заказам** (вкладка «Отчёт», часть 3). Строка на каждую позицию заказа с характеристиками («Основа»,
   «Цвет», «Патина», «Блеск», «Ткань», остальные — в «Прочее»), номер, дата и заказчик — на первой строке заказа. Период,
   месяц, статус, сортировка и счётчик — как в legacy; строки загружаются при первом открытии вкладки.
   - Исправлено (ADR-0002, п. 50): «Период» включает свой первый день. Legacy брал начало периода как полночь UTC,
     в Алматы это 05:00, и заказы первого дня выпадали. Месяцы списка — по заказам своих каналов.
   - «📥 Выгрузить в Excel» — с остальными выгрузками (ERP-067).
7. **Исправлено в журнале заказов** (ADR-0002, п. 42–46):
   - разбивка по статусам в сводке (в legacy всегда пустая);
   - фильтр «В производстве» (в legacy не находил ничего);
   - стрелки сортировки в каждой таблице;
   - счётчики вкладок и список продавцов — только по своим каналам;
   - даты с двузначным годом — полностью.
