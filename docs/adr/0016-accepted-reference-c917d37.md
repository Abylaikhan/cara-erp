# ADR-0016. Новый принятый эталон legacy: `c917d37`

Статус: **принято**. Дата: 15.10.2026. Основание: решение заказчика 15.10.2026 — перенос по актуальной версии `index.html`
(ERP-001, вопрос №3 трекера).

## Контекст

С 13.10.2026 перенос шёл по эталону `c5e745c`. Аудит `20261014T214438Z-6342` наблюдает в legacy версию `c917d37`
(blob `0b5a457`, SHA-256 `85ed7278…`): функции +108 / −0 / ~25, изменены 5 страниц и 1 модальное окно. Новое в legacy:

- вкладка CRM «📐 Проекты» — запросы на расчёт нестандартной мебели: версии расчёта, файлы, обсуждение, исполнители, заказ
  из проекта (4 новые таблицы);
- вкладка «Продаж» «🔧 Реставрации» — гарантийный и платный ремонт, забор и возврат по рабочему листу реализации
  (2 новые таблицы, тип строки рабочего листа);
- «CRM» у начальника цеха и дилеров: они видят в CRM только «Проекты» (`prjApplyRole`);
- PIN: 6 цифр, кнопка «OK» для 4-значного кода, блокировка после 5 ошибок подряд (в `localStorage` браузера);
- пользователи из таблицы `app_users` накладываются на встроенные роли: свои разделы, пароль, блокировка
  («Пользователь заблокирован» при входе), коды ЗП сотрудников на странице пользователей;
- дашборд: график ФОТ считает только статьи зарплатной ведомости; правки рабочего листа реализации и карточки сотрудника.

## Решение

1. Принятый эталон — `c917d37` (`tools/harness/config.json` → `source.accepted_ref`). `make visual-compare` сверяет с ним.
2. Копия данных legacy обновлена (только GET): снимок `20261014T214659Z` — 44 таблицы (новые: `projects`, `project_calcs`,
   `project_files`, `project_comments`, `restorations`, `restoration_files`), 242 GET-запроса, других методов — 0. Проектов и
   реставраций в legacy пока 0. Все перенесённые разделы загружены заново; сверка — 0 расхождений.
3. Перенесено в этом изменении:
   - роли: «CRM» у начальника цеха и дилеров (`config/erp.php`);
   - режим «только Проекты» (`Erp::crmProjectsOnly`): вкладки CRM, кроме «Проектов», и «+ Новый заказ покупателя» скрыты,
     подзаголовок «Проекты · расчёт нестандартной мебели», вкладка открыта сразу. Сервер не отдаёт таким пользователям лиды,
     задачи, клиентов и доски заказов и не даёт их менять (политики лидов и задач). Legacy узнаёт начальника цеха по логину
     `foreman`; здесь — по роли;
   - вкладки «📐 Проекты» (CRM) и «🔧 Реставрации» («Продажи») на своих местах; содержимое — сообщение, когда раздел
     появится (ERP-079, ERP-080; ADR-0002, п. 56);
   - «Рабочий лист реализации» и «Реставрации» скрыты у учётных записей салонов и дилеров (`swApplyRole`; скрытие листа было
     и в `c5e745c`, но не было перенесено);
   - экран входа: PIN на 6 цифр с «OK»; сообщение об ошибке PIN держится 2,5 с; «Пользователь заблокирован» — если
     заблокированный пользователь ввёл верный пароль (при неверном — прежнее «Неверный логин или пароль»).
4. Не перенесено сейчас:
   - блокировка PIN после ошибок: legacy хранит её в браузере; здесь попытки ограничивает сервер. Сам вход по PIN — вместе
     с сотрудниками (M17);
   - пользователи из `app_users`: в legacy одна запись меняет разделы встроенной роли «Гл. бухгалтер» (+8 разделов, −1).
     Здесь действует шаблон роли (ADR-0001), пока не перенесено управление пользователями (ERP-053) и не принято DEC-13;
   - график ФОТ дашборда, правки рабочего листа реализации и карточки сотрудника — с переносом этих разделов (M01, ERP-049/050,
     M17).
