# ADR-0011. Закупки (M04), часть 1: заявки на материал и план-факт

Статус: **принято**. Дата: 14.10.2026. Источник legacy: page-purchases L2884–2993, newMaterialRequestModal L3011;
`initPurchasesExtra`/`showPurchExtraTab`/`setMreqView`/`saveMaterialRequestManual`/`updateMaterialRequestStatus`/
`renderMaterialRequests`/`updatePurchKpis`/`renderMaterialRequestsKanban`/`renderPlanFact`/`renderNormsGrid` L34416–34640.

## Решения

1. **Что показывает раздел.** Старые закупки (`purch_orders`) в legacy отключены заглушками и на странице не видны
   (D-07), здесь их тоже нет. Видимая часть — заявки на материал, поступления, план-факт и нормы расхода.
2. **Заявки на материал.** Таблица и канбан, фильтр по статусу, поиск, KPI и «+ Заявка вручную» — как в legacy.
   - Статус идёт только вперёд: «Заявлено» → «Взято в закупку» → «Пришло на склад». Сервер не даёт перескочить шаг и
     проверяет версию записи; каждое изменение пишется в журнал.
   - «Пришло на склад» склад не двигает, как и в legacy. Приход материала — складской документ (ERP-039/046, решения
     D-04/D-05).
   - «Заявил» — автор заявки. В legacy поле не заполняла ни ручная заявка, ни заявка из рабочего листа, поэтому в
     колонке всегда было «—».
   - Дата заявки — по поясу Asia/Almaty. Legacy отрезал дату от времени в UTC, и заявка, созданная до 05:00 по Алматы,
     показывалась вчерашним днём.
3. **План-факт** считает сервер по правилам legacy: «Нужно» — сумма открытых заявок по названию материала (единица —
   из первой заявки, иначе со склада), «Куплено» — по накладным, «Остаток» — остаток материала с тем же названием,
   «К покупке» = Нужно − Остаток, не ниже нуля; больше всего к покупке — выше. Количества точные (numeric).
4. **Поступления и нормы расхода.** В данных legacy нет ни одной накладной и ни одной технологической карты.
   - Вкладка «Поступления» показывает пустой журнал, «+ Новая накладная» сообщает, когда накладные появятся: накладная
     сопоставляет материалы и закрывает заявки, а что приходует склад — решение D-04 (ERP-046).
   - «Нормы расхода» показывают текст legacy о пустых технологических картах (ERP-028, решение D-12).
5. **Права — как в legacy:** «Закупки» есть у директора, кладовщика и закупщика; у действий legacy своих проверок нет,
   здесь каждое действие проверяет доступ к странице.
6. **Перенос данных:** `make legacy-import ENTITY=material_requests` — 1 заявка, SQL-сверка всех полей и времени —
   0 расхождений.
