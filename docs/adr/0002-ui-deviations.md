# ADR-0002. Отклонения интерфейса от legacy

Статус: **предложено, требует подтверждения заказчиком** (принятие интерфейса — за заказчиком). Дата: 14.10.2026.

Интерфейс копируется 1:1 (стили legacy перенесены без изменений, сравнение скриншотов ≤ 0,09 % при допуске 0,5 %).
Ниже — сознательные отличия с основанием.

| № | Legacy | Новая версия | Основание |
|---|---|---|---|
| 1 | На экране входа блок быстрых подсказок с логинами и паролями всех ролей (L1938) | Блока нет | AUTH-01: пароли/PIN не выдаются в HTML |
| 2 | Диагностическая панель «Диагностика загрузки» сверху экрана (L1823) | Нет | Временная отладочная панель, не часть продукта |
| 3 | Статические бейджи «3» у «Производства» и «2» у «Закупок» | Нет, пока нет реальных счётчиков | Числа не связаны с данными (демонстрационные) |
| 4 | Для `expense_cats`, `esf`, `payroll`, `accruals`, `salon_report` в шапке выводится сырой id (нет в `titles`, L16330) | Название пункта меню | Дефект отображения |
| 5 | Колокольчик открывает «Производство» любой роли | Ссылка только при доступе к разделу | Доступ проверяется сервером (ADR-0001) |
| 6 | Оверлей «Загрузка данных…» при первичной загрузке | Нет: данные приходят с сервером страницы | Нет клиентской загрузки всей базы |
| 7 | PIN-вход открывает кабинет сотрудника | Сообщение «Вход по PIN появится после переноса раздела «Сотрудники»» | PIN принадлежат сотрудникам (M17) — временно |
| 8 | Нет данных справочника: «…Проверьте таблицу expense_categories в Supabase.» | «Нет данных.» | В новой системе нет Supabase |
| 9 | Шрифты IBM Plex с Google Fonts | Те же шрифты из пакета `@fontsource` | Нет внешней зависимости при работе |
| 10 | Неперенесённые разделы | Пункт меню есть, страница честно сообщает, что раздел не перенесён | Не показывать фиктивные данные (ТЗ §1) |
| 11 | Каталог: «Диапазон цен» при пустой выборке — «₸∞ — ₸-∞» | «—» | Ошибка отображения |
| 12 | Каталог: «+ В заказ» открывает форму нового заказа | Сообщение «Создание заказа появится после переноса раздела «Продажи»» | M09 ещё не перенесён — временно |
| 13 | «Покупатели»: «ТОО …», «ИП …» с типом «client» показаны как «Физ. лицо» (`\b` в JS не видит границу слова у кириллицы) | «Юр. лицо»; KPI считают так же | Дефект определения типа (ADR-0006, п. 4) |
| 14 | Окно покупателя: «Заведён: office» — служебный код канала | «Заведён: Офис (прямые продажи)» — название из справочника каналов | Код не предназначен для пользователя |
| 15 | Окно «Изменить лицо» не открывается (id строкой против числа, TypeError) | Открывается, сохраняет запись по id | Дефект (ADR-0006, п. 6; QA-041) |
| 16 | «Покупатели»: вкладки «Салоны», «Сверки»; «Оборот» и «Заказов» по офисным заказам | Сообщение о переносе вкладки; «—» в колонках | M08 переносится частями, заказы (M09) ещё не перенесены — временно |
| 17 | «Дилеры»: «Кол-во заказов», «Оборот» и KPI «Заказов от дилеров», «Оборот» — `0`, `₸0`, `₸0.0М`, пока заказы не загружены | «—» | Заказы (M09) ещё не перенесены; ноль выглядел бы как «заказов нет» — временно |
| 18 | «Дилеры»: кнопка ✕ ничего не удаляет (id передаётся строкой); подтверждения нет | Удаляет (деактивирует) дилера после подтверждения; дилера с ролью, учётными записями или покупателями удалить нельзя | Дефект; удаление теперь сохраняется в базе (ADR-0006, п. 12) |
| 19 | «Дилеры», импорт CSV: повторный импорт добавляет дубли; файл не в UTF-8 даёт искажённые названия; добавленные строки — внизу списка | Дилер с тем же названием второй раз не добавляется («уже есть в списке: N»); файл не в UTF-8 отклоняется; добавленные — вверху, как при «+ Строка» | Идемпотентный импорт (DATA-01), нет искажённых данных (ADR-0006, п. 13) |
| 20 | «Поставщики»: «Импорт из ЭСФ», «Осиротевшие в операциях», «Разночтения написаний», «Сократить юрформы»; список ЭСФ в карточке | Сообщение, когда функция появится; в карточке — «ЭСФ поставщика появятся после переноса раздела «Входящие ЭСФ»» | Функции работают с неперенесёнными разделами «Деньги» и «Входящие ЭСФ» — временно (ADR-0007) |
| 21 | «Склад», KPI «🔴 Критично»: после загрузки показывает критичные и «мало» вместе (renderWarehouse перекрывает renderWhKPIs), «Мало» считает те же позиции ещё раз | Только критичные; «Мало» — отдельно | Двойной счёт; на текущих данных обе плитки равны 0 (ADR-0008) |
| 22 | «Склад»: встроенные демонстрационные документы (П-001…, ТН-001…, ОПР-001) в «Документах», остатках и списаниях «Цехов» | Документов нет: «Складских документов пока нет», в «Цехах» нули | Не данные (D-14); документы — ERP-039 после D-04/D-05 |
| 23 | «Все остатки»: все ячейки редактируются, но правка теряется; «Остаток» тоже редактируется; ✕ убирает строку без вопроса до перезагрузки | Название, SKU, единица, минимум, цена сохраняются; «Остаток» не редактируется (меняется документами); ✕ — подтверждение и удаление только без остатка | Дефект; остаток двигают документы (ADR-0008, п. 3–4) |
| 24 | «Инвентаризация»: склады из старого списка групп, все материалы — в «Прочих материалах»; «Применить» меняет только память страницы; расхождение с артефактами дробей (0.30000000000000004) | Физические склады материала; «Применить» объясняет, что это документ (D-05); расхождение до 0,001 | Дефекты; применение — ERP-040 |
| 25 | «Алиасы»: «+ Добавить алиас» и «+ Алиас» не открывают форму (функции нет / нет поля ошибки); каждый алиас показан дважды; пустой список — «Загрузить из Supabase» | Форма открывается, список поставщиков заполнен, предпросмотр работает, есть строка ошибки; алиас показан один раз; «Алиасов пока нет.» | Дефекты; в БД каждый алиас записан дважды (ADR-0008, п. 6) |
| 26 | «Склад»: «📥 Приход», «↔️ Перемещение», «📤 Списание» и кнопки «Цехов» открывают документ | Сообщение, когда функция появится | Документы ждут D-04/D-05 (ADR-0008) — временно |
| 27 | «+ Материал», шаг 2: материал получает код категории формы («lumber») и остаётся только на странице; количество вводится; список позиций категории — весь | Поле «Категория на складе» (по умолчанию подобрано по данным); количество выключено (остаток — приходом); список позиций категории — 10 строк и «… и ещё N»; «(без SKU)» в сообщении о дубле | Код не совпадал с категориями справочника; остаток двигают документы (ADR-0008, п. 9–12) |
