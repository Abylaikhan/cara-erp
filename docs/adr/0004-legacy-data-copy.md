# ADR-0004. Копия данных legacy: только чтение, локально, с проверкой

Статус: **принято**. Дата: 14.10.2026. Основание: поручение заказчика «перенести все реальные данные, в Supabase строго
только чтение»; ТЗ MIG-01…MIG-03, D-01, AUTH-01.

## Решение

1. **Только чтение.** `php artisan legacy:snapshot` использует `App\Legacy\SupabaseReadOnlyClient`: у клиента есть только
   GET к `/rest/v1/<таблица>`; методов записи и вызова `/rpc` нет. Каждый запрос пишется в `requests.log` снимка, в
   manifest — счётчик методов; при любом не-GET запросе команда падает. Адрес и ключ — только в локальном `.env`.
2. **Полнота и согласованность.** Таблицы — все 38, к которым обращается legacy (статический реестр). Каждая читается
   страницами по 1000 строк в порядке ключа; точное число строк сервера сверяется до и после чтения, при расхождении таблица
   перечитывается (до 3 попыток), иначе статус `CHANGED_DURING_READ` и ненулевой код выхода.
3. **Секреты не копируются.** Столбцы паролей, PIN и токенов зануляются при чтении (`config/legacy.php → redact_columns`):
   новая система не использует старые секреты (AUTH-01, D-13).
4. **Хранение.** Снимок — `.local-audit/supabase/<id>/` (JSON Lines + manifest + журнал запросов), права 0700/0600,
   исключён из Git и из образов Docker. Персональные данные не попадают в репозиторий, отчёты аудита, логи и запросы к модели.
5. **Загрузка.** `php artisan legacy:load` кладёт снимок в отдельную схему `legacy` локальной БД (`legacy.rows`, jsonb,
   представления `legacy.<таблица>` на последний снимок) и сверяет каждую таблицу: число строк и хеш содержимого после
   записи в БД равны снимку. Таблицы приложения не меняются. В production команда не работает.
6. **Перенос в разделы.** `php artisan legacy:import <таблица>` — только для перенесённых модулей: проверка всех строк до
   изменений, одна транзакция, повтор без дублей, соответствие старых и новых ID в `legacy_id_map`, проверка результата.
   Первый — `expense_categories` (M14). Остальные таблицы ждут своих модулей в схеме `legacy`.

## Ограничения

Копия через REST содержит данные, но не DDL: ограничения, индексы, триггеры, RLS и функции БД по-прежнему нужно получить
от владельца (вопрос заказчику №6). Таблицы, к которым legacy не обращается, этим способом не обнаруживаются.
