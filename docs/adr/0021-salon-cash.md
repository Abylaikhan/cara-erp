# ADR-0021. Касса салона (M15), часть 1: просмотр (ERP-051)

Статус: **принято**. Дата: 16.10.2026. Источник legacy (`8d275a1`): `page-money_salon` L7064–7137; `renderSalonMoney`,
`reloadSalonMoney`, `smSort` L15576–15725; `cashAccountId` в `_USERS`.

## Решения

1. **Чья касса.** Салон видит свою кассу, начальник салонов (роль без канала) — обе. Касса роли — `cash_account` в
   `config/erp.php`: legacy-id счёта (legacy `cashAccountId`), найденный через `legacy_id_map`. Страница доступна только ролям
   с «Кассой салона». Сервер отдаёт операции только этих касс.
2. **Как в legacy:**
   - фильтры: период, приход/расход, поиск по описанию и номеру заказа;
   - сортировка по дате, описанию, приходу, расходу;
   - KPI: остаток по всем операциям; поступления и расходы за период; «Передано в офис» — расходы с «офис» в описании или с
     категорией `transfer`;
   - бегущий остаток.
   - Порядок строк как в legacy: кассы друг за другом (Армада, потом Назарбаева), внутри — дата по убыванию.
3. **Отличия:**
   - «Текущий месяц» и «Квартал» заканчиваются бизнес-датой (legacy брал дату UTC — в Алматы до 05:00 вчерашнюю);
   - номера заказов берутся и из оплат по заказам, как в «Деньгах»;
   - legacy читал не больше 1000 операций на кассу — сейчас их по ~230, здесь без предела.
4. «📥 Приход» проводит деньги и ждёт ERP-031…033 (D-03, D-11) — сообщение (ADR-0002, п. 78).

## Проверка

`tests/Feature/Money/SalonCashTest.php`; `make visual-compare` под начальником салонов — 0,02–0,03 %, таблица (451 операция)
совпадает с legacy построчно.
